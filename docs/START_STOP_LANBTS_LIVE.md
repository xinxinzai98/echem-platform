# 蓝博本次测试实时数据

状态：0.7.0-dev.2 曾部署，但大文件上线验收失败，已回退至 0.7.0-dev.1；此功能目前未在线启用。小文件和合成验证通过不能替代大文件验收。

## 分页增量修正（0.7.0-dev.3 待发布）

- 使用厂商 `RecordCache.GetRecord(index)` 分页接口，同一快照只打开一次只读记录缓存，避免反复按循环/工步重新扫描大文件。电压、电流继续使用厂商校准，不自行猜测 ADC 换算。
- 每页最多 65,536 个记录位置；完整测量记录写入独立 SQLite 工作缓存。首轮分批补齐，下一轮只转换新增记录。每次重读并核对已缓存原始记录前缀的 SHA-256 及校准上下文；旧记录改变、文件缩短或上下文改变则重建派生缓存。
- 页面显示分块进度；断网可从已提交位置恢复。截断、缺号、重复号、校验不匹配不会推进游标。首次读取固定目标位置，期间新追加的记录留至下一轮，不会为了追赶持续写入而一直不发布结果。
- 阶段统计只更新收到新点的工步；完整循环由阶段统计配对。缓存保存全部测量记录，网页曲线仍按显示上限抽样；计算不基于显示抽样。
- 读取器的文件流经验证为只读；完成副本准备后释放共享锁，不长时间阻塞通道状态监控。
- 固定 601 点样例的电压、电流、时间、记录号、步骤及循环标记与旧 SDK 导出逐项一致。真实通道 2 首读 738,339 点约 98 秒，再读仅新增 89 点约 7.4 秒；通道 3 首读 737,566 点约 92 秒，再读 95 点约 7.1 秒；通道 6 从中断缓存恢复后达到 739,526 点，再读 423 点约 8.6 秒；通道 7 11,875 点约 4.7 秒，再读 10 点约 4.5 秒。数据持续写入，计数仅为验证时快照。
- SSH 分块读取不复用连接，使用定长 Base64 输入帧及行尾刷新；只读失败最多重试 3 次。页面保留上一份已验证结果并显示错误。

以下保留初版规则及失败经过；分页版本不再受“单份完整 CSV / 1,000,000 行”的内存读入方式约束，改为逐页校验和磁盘缓存。正式历史蓝博数据仍未重算。

蓝博通道卡片增加“查看本次测试数据”。可以在测试未结束时查看连续电压、电流、已闭合循环的末端电位、负移及异常判断，沿用稳定性图表的缩放、框选、平移和复位操作。

## 数据规则

- 用户确认：仅接续同一次测试；不合并不同 BTS 文件。一次刷新替换该 run_id 的旧快照，不把同一段数据反复追加。
- SDK 仅读取本次创建的 BTS 副本。复制时固定长度，重新读取相同长度的源前缀核对 SHA-256；允许仪器在尾部追加，不接受复制过程中已有前缀被改写。
- 完整记录用于计算，再对网页曲线抽样显示。CSV 行数与提取计数必须一致；无效、冲突、截断数据拒绝发布，保留上一份快照。
- 连续时间保留原计时；工步计时回零时优先用记录的绝对时间接续。绝对时间不可用时，以前段累计时间作为起点，不补造缺失采样间隔；结果记录接续方式和次数。
- **按实际高负载→恢复工步顺序配对**，不把仪器 cycle_id 直接当作完整物理循环。实机发现 cycle_id 会在充电起点变化，直接分组会错配相邻循环。
- 阶段最后 1 s 中位数作为末端电位；高负载最低点在前 15 s 为异常。只有恢复段之后已出现下一工步，或测试明确完成，才确认该循环闭合。当前末尾工步只进入全程曲线，不作为已完成循环。
- 电压仍为 LANBTS 原始标尺，不换算 RHE，不套用工作站水位补偿；电流密度只使用本次测试已保存的电极面积。

## 更新和权限

- 沿用“运行与绘图配置”的实时预览开关，每 5 分钟尝试更新运行通道，串行抓取避免并发访问 SDK。耗时抓取会排队；页面显示实际快照时间。
- 服务器本机可点击“读取快照并计算”。局域网只读入口仅查看已生成的缓存，不能触发远端读取或修改配置。
- `GET /api/start-stop/lanbts/live` 返回脱敏共享快照；`POST` 只接受当前有效的 `run_id`。不接收客户端任意路径。
- 快照保存于共享发布目录旁的 `lanbts-live.json`，不写入正式材料数据库，不替换已封存图集。更换测试后，旧 run_id 不在当前通道显示。
- 单个 BTS 副本上限 512 MiB、标准化 CSV 上限 128 MiB / 1,000,000 记录。超限或抓取失败会明确提示，不以抽样代替正式计算。
- SDK 可能持有临时副本句柄直到进程退出。清理失败不丢弃已验证结果；后续抓取仅清理本功能超过 10 分钟的 GUID 临时副本，不清理仪器源文件。

## 本次验证

- 合成测试覆盖工步时间回零、重复记录与冲突、末尾未结束循环、SDK 编号在充电起点变化、刷新替换缓存、失败保留缓存、LAN 写入拒绝。
- Windows SSH 脚本改用定长 Base64 帧，避免等待不稳定的 stdin EOF，同时保留中文路径的 UTF-8 编码；脚本执行后由外层释放看门狗。
- 真实通道 7 的中文命名运行文件已读取 2,345 条记录，4 个工步；正确识别 1 个闭合循环和待闭合的第 2 个循环，SDK 提取约 2.76 s。不同抓取间记录数增长，但没有重复累加。
- 独立本地合成浏览器检查了 1440×900、1920×1080 两种桌面尺寸，指标切换及缩放 100%→133%→100%。截图位于 `output/playwright/lanbts-live-20260908/`。

本次没有重算历史正式蓝博数据。旧版按 SDK 编号分组的结果可能与新的工步配对不同；正式历史结果需单独迁移核验后，才宜与此实时计算作定量对比。工作站启停计算不变。

## 2026-09-08 上线验收与回退

- 源码提交 `dbad6ca55474f6f6d56fd6b6e01f0bd7e5f91d02`，镜像 `0.7.0-dev.2-windows`；构建和隔离容器流程通过，56 个运行文件哈希、19 个静态资源一致。
- 线上四个活动通道中，长时间测试 BTS 约 94–119 MB。全量转换超过 180 s 截止时间，且长读取会占用共享读取锁，首轮没有发布有效实时快照。不能称为上线验收通过。
- 尝试的原生 CSV 格式化、字段访问缓存和全记录接口也未通过最大文件的限时验证；未发布这些实验性代码。保存于 `output/releases/lanbts-live-dev2/experimental-native.patch` 和 `experimental_native_csv.py`。
- 已恢复 0.7.0-dev.1、原实时预览开启状态，以及 generation 100 的历史分析；没有重算或删除原始数据。
- 另确认“空间不足”来自 4 GiB tmpfs 工作区，预估需求仅超约 3.5 MB，而主机磁盘仍有约 977 GB。已改为独立磁盘缓存卷 `start-stop-analysis-scratch`，最终 `preflight_ok=true`、`shortfall_bytes=0`、无受限角色。
- 新实时功能仍需解决大文件首次读取与增量缓存的吞吐问题，并验证四个真实活动通道后再部署。部署脚本、回退脚本和状态证据保留在 `output/releases/lanbts-live-dev2/`。

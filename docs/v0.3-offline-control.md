# V0.3 阶段 A：CHI 离线协议编译

## 阶段目标

阶段 A 只建立“协议 JSON → 严格校验 → 内存宏 → 静态复核 → 可选写入新文件”
这条离线链路。开发和验证都可以在 Mac 完成，不需要连接 Windows。

本阶段明确没有仪器运行入口：不会启动 CHI、不会调用 `/runmacro`、不会访问串口，
也不会把宏复制到 Windows。

## 支持范围

当前协议 schema 版本为 `1`，支持：

- CV：初始、高低电位、方向、扫描速率、扫描段数或受限的圈数换算、采样间隔、
  静置时间和自动/固定灵敏度
- OCP：记录时长、采样间隔、静置时间和上下限
- LSV：起止电位、扫描速率、采样间隔、静置时间和自动/固定灵敏度
- EIS：OCP/固定电位偏置、高低频、振幅和静置时间

EIS 的 Points/Decade 还没有形成经过确认的宏参数映射，因此 schema 会拒绝这个
字段，并要求在 CHI IMP 参数页人工复核。EIS 时长也不会伪造为精确值。

## 使用方式

先复制并编辑公开示例。示例中的数值只用于验证字段和编译流程：

```sh
cp docs/chi-protocol.example.json /tmp/my-protocol.json
python3 scripts/compile_chi_protocol.py \
  /tmp/my-protocol.json \
  --output-folder D:/EchemPlatform/Runs/RUN-DEMO-001 \
  --allowed-run-root D:/EchemPlatform/Runs
```

上面的命令只校验和内存编译，并打印 JSON 报告。需要保留二进制时再增加：

```sh
--macro-output /tmp/RUN-DEMO-001.mcr
```

目标 `.mcr` 必须不存在；编译器不会覆盖旧文件。报告中的两个字段应始终为：

```json
{
  "instrument_started": false,
  "instrument_control_enabled": false
}
```

## 校验顺序

1. 拒绝未知 schema 字段、错误类型、非有限数值和越界值。
2. 规范化技术名称、CV 段数和可选默认值。
3. 检查工步 id、保存名及大小写不敏感的重复输出。
4. 检查 Windows 输出目录必须位于允许根目录之下。
5. 生成固定文件头和 ASCII 宏正文。
6. 从生成的二进制重新解析每条命令。
7. 检查白名单、禁止命令、工步顺序、参数集合和保存配对。
8. 生成协议与宏的 SHA-256 报告。

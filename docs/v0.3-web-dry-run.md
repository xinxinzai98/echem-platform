# V0.3 阶段 B：网页协议 Dry-run

## 阶段目标

阶段 B 把阶段 A 的严格协议模型和 CHI 宏编译器接到本地网页，但只提供“编辑 →
保存草稿 → 校验 → 生成内存预览”链路。开发与验证仍在 Mac 完成；未来部署后，页面
在仪器 Windows 电脑本机浏览器打开。

本阶段没有仪器运行入口，不连接 Windows、不启动 CHI、不执行宏、不访问串口，也
不把 `.mcr` 文件写到磁盘。

## 页面能力

打开 `http://127.0.0.1:8787/protocol` 后可以：

- 编辑协议名称、匿名样品编号和可选说明字段
- 设置允许的 Windows 运行根目录和本次新输出目录
- 添加 CV、OCP、LSV 和 EIS 工步
- 复制、删除、启用、禁用和调整工步顺序
- 自动保存或手动保存本地 SQLite 草稿
- 仅执行校验并查看字段级错误
- 生成规范化工步、目标 BIN/TXT 文件、预计时长、警告和 CHI 宏文本预览

公开默认草稿只用于展示字段格式，不代表任何材料、电解液或电极体系的推荐参数。

## 本地接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/control/capabilities` | 返回支持技术和强制关闭的控制能力 |
| `GET` | `/api/protocols` | 列出本机草稿摘要 |
| `GET` | `/api/protocols/{id}` | 读取一份草稿；默认草稿不存在时返回公开格式示例 |
| `POST` | `/api/protocols` | 保存草稿和递增修订号 |
| `POST` | `/api/protocols/validate` | 严格校验，不返回宏正文 |
| `POST` | `/api/protocols/compile` | 在内存中编译并返回当前请求的宏预览 |

不存在 `/start`、运行队列、进程启动、宏投递或串口控制接口。

## 草稿与校验的区别

草稿保存用于保留编辑进度，因此允许保存缺字段、重复文件名或其他尚未通过校验的
内容。点击“仅校验”或“生成 Dry-run 预览”时，服务端会重新执行阶段 A 的全部
schema、路径、白名单和静态宏复核，不能依赖浏览器端检查绕过安全规则。

参数发生变化后，页面会立即作废旧校验结果和旧宏预览。校验失败时返回稳定的错误
码、字段路径和中文说明，并保持宏预览隐藏。

## 预计时长与人工复核

- CV 按规范化扫描路径、扫速和静置时间估算
- OCP 按记录时长和静置时间估算
- LSV 按电位跨度、扫速和静置时间估算
- EIS 受低频周期、稳定过程、自动量程和设备参数影响，不显示虚假的精确时长
- 未确认映射的 EIS Points/Decade 不进入宏，必须在未来的 CHI IMP 参数页人工复核

页面显示的时间仅用于排程预览，不是仪器联锁或安全上限。

## 强制安全状态

能力接口和每次编译报告都保持：

```json
{
  "instrument_control_enabled": false,
  "instrument_started": false,
  "launch_available": false,
  "serial_access": false
}
```

网页只连接同一台电脑上的回环服务。服务仍拒绝绑定局域网地址，不调用外部网络
服务，协议草稿和平台数据库都留在本机。

## 下一阶段门槛

Windows 端宏导入检查、CHI 交互会话、演示参数空载测试和真实仪器闭环是彼此独立的
后续阶段。任何一个阶段都需要新的明确确认、可回滚方案、现场安全条件和相应测试；
阶段 B 的“校验通过”不能当作上机授权。
